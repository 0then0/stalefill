# StaleFill 0.2.0

This release adds hash cache fills and single-key transactional hash publications. Existing string and negative-cache scenarios use the same version-1 configuration.

## Hash and transaction support

HGET, HMGET and HGETALL recognize supported cache misses. Standalone HSET can be held before forwarding. A supported MULTI/EXEC fill contains optional DEL/UNLINK, one or more HSET commands and optional EXPIRE/PEXPIRE, all on the selected key. The proxy holds EXEC before forwarding and requires successful transaction replies before counting publication as complete.

Queued deletes inside the reader's fill do not satisfy the writer's invalidation barrier. Discarded, rejected and aborted publications produce SF008. Same-connection invalidation behind a held fill produces SF006 and promptly cancels the waiting HTTP probe.

Lua commands with valid declared keys unrelated to the selected cache key pass through. Target scripts remain unresolved; script source and ARGV are not interpreted. Reports add a bounded `fill_mode` without exposing cache contents or scripts.

## Client compatibility

The bundled redis-py 8.1.0, go-redis 9.22.0 and node-redis 6.3.0 fixtures were checked in RESP2 and RESP3 on Redis 8.10.2 and Valkey 9.1.2. Every combination completed 24 broken and 24 protected schedules with the expected outcomes and zero schedule misses. Standalone hash publication was also checked using redis-py.

See [client compatibility](https://github.com/0then0/stalefill/blob/v0.2.0/docs/client-compatibility.md) for reproduction commands and the limits of these checks. The fixtures use an in-memory authoritative store; the protected mode checks the HTTP invariant through an authoritative version lookup.

## Scope and distribution

Single-node TCP remains the transport scope. Arbitrary transactions, target Lua, Redis Functions, CLIENT TRACKING, asynchronous pushes, Cluster, Sentinel and TLS are unsupported. See [architecture](https://github.com/0then0/stalefill/blob/v0.2.0/docs/architecture.md) for exact patterns and bounds.

The core Go module remains dependency-free; client fixtures have separate pinned manifests. Release checks include both server families and the client compatibility workflow. Archive targets remain Linux amd64/arm64, macOS amd64/arm64 and Windows amd64, with `SHA256SUMS`. Archives contain the CLI, examples and documentation; fixture programs require a source checkout.
