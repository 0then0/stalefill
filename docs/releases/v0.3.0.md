# StaleFill v0.3.0

Development release candidate: Detached / Asynchronous Fill Scheduling.

An HTTP reader can complete after loading V1 while a background worker publishes it later. StaleFill now retains that old observation, associates one compatible publication with the confirmed miss, and continues the existing hold/write/invalidation/authoritative/release/verify schedule. A synchronous fill still starts the writer as soon as its publication is held.

Baseline reads join their observed publications before subsequent mutation and before race prepare. The existing invocation timeout bounds all joins and association; no additional timeout setting or dependency is required. Optional `read/verify.cache_publication: "none"` declares a baseline probe that intentionally does not fill, for example verification of a present record in a negative-only cache. Writer cache lookups after the hold preserve the reader episode, and HTTP failures caused by scheduler refusal retain the original finding. Missing publication is UNRESOLVED SF005. Competing candidates/reads/misses, incompatible publication shape/order and unexpected early reader values are UNRESOLVED SF009 with explicit reason events. Transaction rejection remains SF008; unsupported protocol/commands remain SF006.

Events now identify miss episodes and miss/fill connections with numeric invocation-local metadata, and timestamp actual HTTP reader completion. Cache values, fields, HTTP bodies and credentials remain excluded. Connection equality is not required for detached fills.

The change follows the [v0.2 gocache evidence](../cases/gocache-v4.4.0.md). The same unmodified dependency and fixture yielded 24/24 completed stale schedules on Redis and 4/4 on Valkey in the [v0.3 local validation](../cases/gocache-v4.4.0-v0.3.md). These finite runs do not establish behavior for every application or interleaving.

Use a disposable isolated target with a single publication producer per miss. No opaque wire-only model can distinguish a lone unrelated publication or hidden delayed retry with identical key/shape/order. Baseline joins establish completion of modeled publications, not global application quiescence. See [architecture](../architecture.md#miss-episodes-and-detached-publication).

Version-1 configurations, supported publication commands, HTTP observation contracts and archive platforms remain compatible. No release, tag or upstream report is published by these local changes.
