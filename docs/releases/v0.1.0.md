# StaleFill 0.1.0

The initial release tests stale-fill-after-invalidation and negative-cache-resurrection races against Redis or Valkey. It holds an old string fill, lets a newer authoritative write and invalidation complete, releases the fill and checks the final cache-backed HTTP response.

## Included features

- GET/MGET misses with SET/SETEX/PSETEX publication barriers.
- Sequential baseline and proxy wiring checks before the race.
- Exact key or anchored regex selection and configured HTTP observations.
- Four explicit outcomes, stable finding IDs and sanitized JSON traces.
- Vulnerable and protected Go demos.

The protected demo checks cached generations against an authoritative snapshot and repairs stale entries on read. It protects the configured API observation; it can still physically publish an old cache entry.

## Compatibility and limits

Version 0.1.0 was tested against Redis 7.4.11 and Valkey 8.1.10 with 24 repetitions per broken/protected positive/negative combination. It supports single-node TCP, RESP2 and non-streaming RESP3 request/reply traffic. Hash scheduling, transactions, Lua, Redis Functions, Cluster, Sentinel, TLS and asynchronous push modes are outside this version's scenario support.

Use isolated integration fixtures. The configured probes perform application writes, including baseline checks. Listener addresses are loopback-only; remote upstreams require explicit opt-in.

## Archives

Available archive targets are Linux amd64/arm64, macOS amd64/arm64 and Windows amd64. Archives contain the CLI, configuration examples, documentation, traces and Apache-2.0 license. Verify downloads against `SHA256SUMS`.
